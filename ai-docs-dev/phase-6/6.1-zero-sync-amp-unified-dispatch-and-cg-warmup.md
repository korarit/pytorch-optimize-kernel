# Plan 6.1: Zero-Sync AMP Watchdog, Unified Module Dispatcher & Single-Pass Training CUDA Graphs

## 1. ปัญหาที่พบจาก Code Review & Profiler (Phase 5)
1. **Forced CPU-GPU Sync ทุก Step ใน `auto_amp.py`**:
   - [`src/passes/auto_amp.py`](../../src/passes/auto_amp.py#L228-L245) (`check_loss_stability`) ถูกเรียกใน `_amp_backward` (บรรทัด 349) บน **ทุก backward step** และสั่ง `loss_tensor.detach().cpu().item()` ทำให้เกิด `cudaStreamSynchronize` คั่นกลางระหว่าง `forward()` กับ `backward()` ทุก step (แม้ใน `bf16` ที่ไม่มี `GradScaler`) ขัดขวาง async CPU-GPU pipelining และ H2D prefetch overlap
2. **Double-Compile Overhead ใน `train_cuda_graphs`**:
   - จาก [`report/065346_20261118-phase-5.4.txt`](../../report/065346_20261118-phase-5.4.txt#L143-L149): [`auto_compile.py`](../../src/passes/auto_compile.py#L403-L437) compile Step 0 ด้วย `mode="default"` (`~6.2–6.9s`) แล้วทิ้งกราฟใน Step 1 เพื่อ recompile ใหม่ทั้งหมดด้วย `mode="reduce-overhead"` (`~8.5–14.6s`) ทำให้ E2E ของ `deep_mlp` (`28.45s`) ช้ากว่า `compile_default` (`27.81s`)
   - นอกจากนี้ ในโปรไฟล์ `aggressive` ที่ตั้ง `compile.mode="max-autotune"`, [`auto_compile.py#L403`](../../src/passes/auto_compile.py#L403) ใช้ `max-autotune` ตั้งแต่ Step 0 (ซึ่ง Inductor เปิด CUDA Graphs ในตัว) โดยไม่เคารพ Dropout/`>15M` guard ของ `train_cuda_graphs`
3. **`nn.Module.__call__` ซ้อน 6 ชั้น + Train/Eval State Conflict**:
   - [`src/passes/registry.py`](../../src/passes/registry.py#L31-L37) ให้ 6 passes monkey-patch `nn.Module.__call__` ซ้อนกัน ทุก submodule call จึงจ่าย 6 Python wrappers + `try/finally`
   - [`inference_opt.py#L565`](../../src/passes/inference_opt.py#L565) และ `auto_compile.py` แชร์ `_compiled_call_impl` เดียวกัน ทำให้ถ้าโมเดลเดียวกันรัน `.train()` ก่อนแล้วค่อย `.eval()`, `inference.cuda_graphs` จะถูกข้ามเงียบๆ (หรือถ้ารัน `.eval()` ก่อน จะค้าง `reduce-overhead` ตอนเทรน)
4. **Blind Spots ของ Nested Container & String Allocation**:
   - `_shape_signature` ([`auto_compile.py#L132-L139`](../../src/passes/auto_compile.py#L132-L139), [`inference_opt.py#L57-L63`](../../src/passes/inference_opt.py#L57-L63)) และ `_has_requires_grad_tensor` ([`inference_opt.py#L47-L54`](../../src/passes/inference_opt.py#L47-L54)) ตรวจแค่ top-level `*args, *kwargs.values()` ไม่ recurse เข้า `dict`/`list`/`tuple` และ `auto_compile.py#L414` ยังแปลง `str(dtype)`/`str(device)` ทุก step

## 3. งานย่อย (Implementation Tasks)
- [ ] **1. Zero-Sync AMP Watchdog + Guardrail #3 (`src/passes/auto_amp.py`)**:
  - เปลี่ยน `check_loss_stability` ให้ไม่เรียก `.cpu().item()` sync ใน `_amp_backward` ทุก step:
    - **Guardrail #3 (ป้องกัน NaN หลุดแก้ Weights ใน `bf16`)**: ห้ามปล่อยให้ `NaN` ข้ามไป step ถัดไปแล้วค่อยตรวจหลัง `optimizer.step()` อัปเดต weight ไปแล้ว! ให้สั่ง async D2H copy (`non_blocking=True`) จาก `loss_tensor` ลง 2-slot pinned CPU scalar buffer + `cuda.Event` ตอนเข้า `_amp_backward` แล้ว **ค่อย sync/ตรวจค่าใน `optimizer.step()` pre-hook** (ยังคง overlap เต็มช่วง `forward ↔ backward` และตัด sync ที่จุด backward ออกหมด โดยไม่ยอมให้ NaN update weights!)
    - คง immediate sync ในโหมด `--strict` หรือเมื่อตั้ง `PTOPT_AMP_WATCHDOG_SYNC=1`
- [ ] **2. Single-Pass `train_cuda_graphs` & `max-autotune-no-cudagraphs` (`src/passes/auto_compile.py`)**:
  - เมื่อ `rt.train_cuda_graphs=True` และ `rt.dynamic` ไม่ใช่ `True`:
    - **Step 0**: รัน eager พร้อมบันทึก shape signature แรก (ไม่เสียเวลา compile `mode="default"` 6–7s แล้วโยนทิ้ง)
    - **Step 1**: เมื่อ shape เดิมซ้ำ (`stable >= 2`) และผ่าน `_is_eligible_for_train_cuda_graphs` ค่อย compile **ครั้งเดียว** ด้วย `mode="reduce-overhead"` (หรือหากไม่ผ่านเกณฑ์ ค่อย compile ครั้งเดียวด้วย `mode="default"` / `"max-autotune-no-cudagraphs"`)
  - เมื่อ `rt.mode == "max-autotune"` แต่ `_is_eligible_for_train_cuda_graphs` ปฏิเสธ (เช่น active Dropout หรือ `>15M` params) ให้ downgrade เป็น `"max-autotune-no-cudagraphs"` แทน `"max-autotune"` เพื่อไม่ให้ Inductor แอบเปิด CUDA Graphs
- [ ] **3. Unified `nn.Module.__call__` Dispatcher & Train/Eval Isolation**:
  - สร้าง `ModuleCallDispatcher` กลางที่เช็ก `depth == 1` เพียงครั้งเดียวและเรียก active pre/context handlers ตามลำดับ (เมื่อ `depth > 1` ใน submodule call ให้เข้า `orig_mod_call` ทันทีโดยผ่านเช็ก boolean เพียง 1 ชั้น; คง `install_*`/`uninstall_*` เดิมให้ unit tests เรียกแยกได้)
  - แยก attribute เก็บ compiled implementation ของ `.train()` (`_ptopt_train_compiled_impl`) กับ `.eval()` (`_ptopt_eval_compiled_impl`) และสลับใส่ `_compiled_call_impl` ตาม `mod_self.training` เพื่อให้โมเดลที่เทรนก่อนแล้วค่อย eval ได้ `reduce-overhead` inference CUDA Graphs ครบ (และ eval ก่อนก็ไม่ทำ train ค้าง `reduce-overhead`)
- [ ] **4. Recursive Input Inspection & Zero-Churn Signatures**:
  - สร้าง helper กลาง `iter_nested_tensors(obj, tensor_cls, max_depth=6)` (มี `seen_ids` / depth cap กัน cyclic container เพื่อไม่ให้ loop ค้าง) ใช้ร่วมกันใน `_shape_signature`, `_has_cuda_context`, และ `_has_requires_grad_tensor` รองรับ `dict`/`list`/`tuple`
  - ใน `_shape_signature`: เก็บ `(tuple(item.shape), item.dtype, item.device)` เป็น tuple ของ object ตรงๆ (ไม่ต้อง `str(...)` ทุก step) และหยุด re-hashing หลังผ่าน N steady steps เมื่อ CUDA Graphs / static compile lock แล้ว (เว้นแต่มี flag check dynamic)
