# Plan 6.2: Hybrid `torch.compile` + `FusedLinearCrossEntropy`, Triton-Backed Activation Checkpointing & OOM Shield

## 1. ปัญหาที่พบจาก Code Review & Profiler (Phase 5)
1. **ต้องเลือกอย่างใดอย่างหนึ่งระหว่าง `torch.compile` กับ `FusedLinearCrossEntropy`**:
   - ปัจจุบัน [`src/kernels/registry.py#L164,L178`](../../src/kernels/registry.py#L164) ปิด `fused_linear_cross_entropy` ทันทีเมื่อ `compile.enabled=True` และ `_lce_head_fwd` (บรรทัด 391) ข้ามเมื่อ `is_compiling()`
   - ผลใน [`report/053832_20261118-phase-5.2.txt#L30-L31`](../../report/053832_20261118-phase-5.2.txt#L30-L31) (`vocab32k`): `balanced_compile` ใช้เวลา `47.56 ms` และ VRAM **`2,815.0 MB`** (เพราะ Inductor ยังต้องสร้าง `[N, V]` logits เต็มก้อน) เทียบกับ `fused_lce_eager` ที่ใช้ `36.78 ms` และ **`1,214.5 MB`** — หากรวม **Inductor บน Backbone + FusedLinearCE บน LM Head** จะได้ทั้งความเร็วสูงสุดของทั้งคู่พร้อมกัน!
2. **`LazyLinearLogits` หลุด Materialize เมื่อ User Cast Dtype + `fp16` Backward Buffer**:
   - [`LazyLinearLogits.__torch_function__`](../../src/kernels/fused_linear_cross_entropy.py#L381-L432) รองรับ `view`/`reshape`/`contiguous`/`__getitem__` แต่ **ไม่รองรับ `.float()` / `.to(dtype)`** (เช่น `F.cross_entropy(logits.float().view(-1, V), y)`) ทำให้หลุดไปเรียก `materialize()` จอง logits เต็มก้อน
   - ใน [`FusedLinearCrossEntropyFn.backward`](../../src/kernels/fused_linear_cross_entropy.py#L219,L274): บน `fp16` (T4 `sm_75`) หรือ `n_chunks > 16` ยัง allocate `[V, H]` buffer ซ้อน (`mm` + `.float()`) ทุก chunk
3. **Activation Checkpointing ความเร็วตก 3x (`4.17x → 1.35x`) และไม่กัน Step-0 OOM**:
   - จาก [`report/074734_20261118-phase-5.5.txt#L20-L23,L65-L91`](../../report/074734_20261118-phase-5.5.txt#L20-L23): เมื่อ [`activation_checkpoint.py#L279-L284`](../../src/passes/activation_checkpoint.py#L279-L284) ปิด `torch.compile` ทั้งโมเดล, โปรไฟล์ `balanced` มี `kernels.enabled=False` จึงตกไปเป็น **pure eager PyTorch** (`aten::mul` + `vectorized_elementwise` พุ่งเป็น `316 ms` และ SDPA ตกจาก `_flash_attention_backward` `17.26 ms` ไป `_efficient_attention_backward` `68.46 ms`)
   - ปัจจุบัน checkpoint **100% ของ blocks** ทันทีที่เกิน 82% VRAM และเช็ก `probe_vram()` **ก่อน** Step 0 forward เท่านั้น หากโมเดล OOM กลาง Step 0 แรกจะล้มก่อนที่ `auto` จะทันทำงาน; อีกทั้ง [`discover_checkpoint_blocks`](../../src/passes/activation_checkpoint.py#L111) กรองด้วย `params >= 100_000` ทำให้โมเดลที่ hidden เล็กแต่ `seq_len` ยาวไม่ถูก checkpoint

## 3. งานย่อย (Implementation Tasks)
- [ ] **1. Hybrid `torch.compile` Backbone + `FusedLinearCrossEntropy` Head**:
  - เมื่อ `compile.enabled=True` และ `out_features >= min_lce_vocab` (เช่น `>= 4096`, และ `sm >= 80` + Triton พร้อม):
    - ห่อ `lm_head.forward` (เฉพาะตอนคืนค่าหรือผ่าน `@torch.compiler.disable` wrapper / `torch.library.custom_op` boundary) ให้ Dynamo graph จบก่อน `lm_head` หรือส่งผ่าน `LazyLinearLogits` ออกไปนอก compiled region เพื่อจับคู่กับ `F.cross_entropy`
    - เปิดให้ `balanced` และ `aggressive` ใช้ Hybrid LCE ได้เมื่อ `vocab >= 8192` (หรือ opt-in threshold via `PTOPT_FUSED_LCE_MIN_VOCAB`)
- [ ] **2. Harden `LazyLinearLogits` & `fp16` Backward Memory**:
  - ใน `LazyLinearLogits.__torch_function__`: intercept `torch.Tensor.float`, `torch.Tensor.half`, `torch.Tensor.bfloat16`, และ `torch.Tensor.to` (เมื่อเปลี่ยนเฉพาะ `dtype` ที่รองรับและไม่ได้ย้าย device) ให้คงความเป็น `LazyLinearLogits` โดยไม่ materialize
  - ใน `FusedLinearCrossEntropyFn.backward`: ลด peak temp buffer ของ `d_weight` เมื่อ `n_chunks > 16` หรือ `fp16` (เช่น split accumulation หรือ group chunks โดยไม่สร้าง `[V, H]` FP32 tensor ใหม่ซ้ำทุก chunk)
- [ ] **3. Triton-Backed & Smarter Activation Checkpointing (`src/passes/activation_checkpoint.py`)**:
  - **Auto-Triton Fallback**: เมื่อ `activation_checkpointing` สั่ง bypass `torch.compile` บนโมเดล ให้เรียก `enable_custom_kernels_on_module(mod_self)` อัตโนมัติ (เปิด `RMSNorm`, `LayerNorm`, `SwiGLU`, `CrossEntropy`, `FusedLinearCE` ในโมเดลนั้นแม้ในโปรไฟล์ `balanced`) เพื่อไม่ให้ร่วงกลับ pure eager
  - **Partial / Strided Checkpointing (`PTOPT_ACT_CKPT_RATIO`, default `0.5` ในโหมด `auto`, `1.0` ใน `always`/OOM retry)**: Checkpoint เฉพาะ 50% ของ blocks (ทุกๆ 2 blocks) ก่อนเมื่อ VRAM แตะ threshold; ถ้ายังเกินค่อยขยายเป็น 100%
  - **Selective Activation Checkpointing (SAC)**: เพิ่ม opt-in/auto support สำหรับ PyTorch `create_selective_checkpoint_contexts` (`_ops_to_save` เก็บ `mm`/`addmm`/SDPA หรือลด recompute attention) เมื่อ PyTorch รองรับและอยู่ในโหมด `balanced` เพื่อรักษา FlashAttention backward
  - **Step-0 OOM Shield**: Catch `torch.cuda.OutOfMemoryError` ใน top-level `Module.__call__` (เมื่อ `mode="auto"` และยังไม่ได้เปิด `act_ckpt`) -> `gc.collect()` + `torch.cuda.empty_cache()` + เปิด `act_ckpt` 100% + retry forward อัตโนมัติ 1 ครั้ง
  - **Block Discovery**: หากcontainer (`ModuleList`/`Sequential`) มี `len >= 4` blocks ให้ลดเกณฑ์หรือพิจารณา activation footprint ไม่ข้าม block ที่มี params `< 100k`
