# Plan 5.5: Zero-Code Auto Activation Checkpointing & Dedicated CUDA Copy Stream Prefetch

## 1. ปัญหาที่พบ & เป้าหมาย
1. **OOM Boundary เมื่อ Batch Size / Sequence Length ใหญ่**:
   - ปัจจุบัน [`src/passes/memory_allocator.py`](../src/passes/memory_allocator.py) ตั้งแค่ `expandable_segments:True` เพื่อลด fragmentation แต่ถ้าโมเดล/batch ใหญ่เกินความจุ VRAM (เช่น `22 GB` บน L4 หรือ `15 GB` บน T4) ผู้ใช้ยังเจอ OOM จนต้องไปแก้โค้ดเพิ่ม `torch.utils.checkpoint` เอง
2. **H2D Transfer Overlap ใน DataLoader (`Vision` / `Multimodal` Batch ใหญ่)**:
   - ปัจจุบัน [`src/passes/dataloader_tune.py`](../src/passes/dataloader_tune.py#L225-L280) จูน `num_workers`, `pin_memory=True` และ promote `tensor.to("cuda")` ให้เป็น `non_blocking=True`
   - แต่ถ้า user script โหลด tensor CPU จาก DataLoader แล้วค่อย `.to("cuda")` หน้า `model(x)` ใน stream หลักทันที เวลาโอน PCIe ยังอาจซ้อนไม่เต็มที่หาก CPU ไม่ได้พรีเฟตช์ batch ถัดไปขึ้น GPU บน **Dedicated CUDA Copy Stream** ล่วงหน้า

## 2. ไฟล์เป้าหมาย
- `src/passes/activation_checkpoint.py` *(ใหม่)* — Auto Activation Checkpointing pass (`auto` trigger ตาม VRAM headroom หรือ opt-in via `--override runtime.activation_checkpointing=auto|always`)
- `src/passes/dataloader_tune.py` — เพิ่ม Dedicated CUDA Copy Stream Prefetcher (`_AsyncCudaPrefetchIter`) ครอบ `DataLoader.__iter__` เมื่อเปิด `dataloader.cuda_prefetch=True` & `pin_memory=True`
- `src/config/schema.py` & `src/config/rules_builtin.py` — เพิ่ม `RuntimeConfig.activation_checkpointing: str = "off"` (`off | auto | always`) และ `DataLoaderConfig.cuda_prefetch: bool = False`
- `src/passes/__init__.py` — ลงทะเบียน `activation_checkpoint` pass ร่วมกับ pass เดิม (รักษา lazy-`torch` invariant)
- `tests/unit/test_pass_actckpt_prefetch.py` — Unit tests ตรวจ `checkpoint(..., use_reentrant=False)`, VRAM threshold trigger, CPU/non-grad skip, `copy_stream` + `record_stream` lifecycle
- `scripts/verify_phase5_5.py` — Experiment วัด Peak VRAM max batch size (`activation_checkpointing`) และ Vision/large-input throughput (`cuda_prefetch`)

## 3. งานย่อย (Implementation Tasks)
- [ ] **Part A: Auto Activation Checkpointing (`src/passes/activation_checkpoint.py`)**:
  - ตรวจโครงสร้างโมเดลหา repeated container/block submodules (`nn.ModuleList` children หรือ block classes อย่าง Transformer/Residual blocks ที่มีพารามิเตอร์พอสมควร เช่น `>= 100k` params และเป็นชั้นกลางที่อยู่ใน `model.training == True` + `torch.is_grad_enabled()`)
  - โหมด `auto` (VRAM-aware): ติดตาม peak `torch.cuda.memory_allocated() / total_vram`; เมื่อ **VRAM > 82%** (หรือ user ตั้ง `always` / `PTOPT_ACTIVATION_CKPT=1`) ให้สลับ forward ของ target blocks ไปใช้ `torch.utils.checkpoint.checkpoint(orig_fwd, *args, use_reentrant=False, **kwargs)` อัตโนมัติ (ข้ามใน `.eval()` / `inference_mode()`!)
  - Fallback guard: ถ้า block คืนค่า complex/non-tensor หรือไม่รองรับ checkpointing -> ถอด hook บน block นั้นกลับไปปกติทันที
- [ ] **Part B: Dedicated CUDA Copy Stream Prefetcher (`src/passes/dataloader_tune.py`)**:
  - เมื่อ `cfg.dataloader.cuda_prefetch == True` + CUDA พร้อม + batch จาก DataLoader เป็น CPU pinned tensors (dict/tuple/list/Tensor):
    - สร้าง 1 dedicated `copy_stream = torch.cuda.Stream()` ต่อ iterator
    - ขณะ user loop กำลังคำนวณ batch ปัจจุบัน (`batch_i`) ให้ pre-stage batch ถัดไป (`batch_{i+1}`) ขึ้น CUDA แบบ non-blocking บน `copy_stream`
    - ก่อน `yield` ให้สั่ง `torch.cuda.current_stream().wait_stream(copy_stream)` และ `tensor.record_stream(torch.cuda.current_stream())` เพื่อป้องกัน memory allocator ยึดคืนก่อน compute เสร็จ
  - **Safety**: หาก batch เป็น nested custom class ที่ย้ายไม่ได้ หรือมี `CUDA` tensors อยู่แล้ว หรือ user script สั่ง `.cpu()` กลับ -> ปล่อยผ่านตรง ๆ แบบ zero-break!

## 4. Tests & Success Criteria
- **Unit (`tests/unit/test_pass_actckpt_prefetch.py`)**:
  - ทดสอบ backward ผ่าน `activation_checkpoint` (`use_reentrant=False`) ได้ gradients ตรงกับ Eager Reference (`allclose`) และ `.eval()` ไม่เสียเวลา checkpointing
  - ทดสอบ mock VRAM > 82% trigger เปิด checkpointing อัตโนมัติในโหมด `auto`
  - ทดสอบ `_AsyncCudaPrefetchIter` ว่า prefetch batch ล่วงหน้า 1 step, คืน tensors ครบไม่ตกหล่น, และ fallback สะอาดเมื่อเจอ custom non-tensor items
- **Benchmark (`report/HHMMSS_YYYYMMDD-phase-5.5.txt`)**:
  - ทดสอบ `transformer_lm` / `cnn_vision` บน L4:

    2. งาน heavy H2D payload (`SyntheticVisionDataset` input ใหญ่) แสดงเวลา H2D overlap ใน profiler (`cuda_prefetch=True`) โดยไม่กระทบ parity
