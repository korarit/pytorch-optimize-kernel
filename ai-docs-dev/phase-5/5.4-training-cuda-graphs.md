# Plan 5.4: CUDA Graphs for Static-Shape Training Loops

## 1. ปัญหาที่พบจาก Benchmark จริง
- ปัจจุบัน [`src/passes/inference_opt.py`](../src/passes/inference_opt.py#L388-L435) เปิดใช้ CUDA Graphs (`mode="reduce-overhead"`) เฉพาะตอน `.eval()` (Inference) เท่านั้น ซึ่งลด latency ของ `infer_bs1_small` ได้ถึง `3.18x` (`1.55 -> 0.49 ms`)
- แต่ในโหมด **Training**:
  - ใน [211155_20261117-phase-4.txt](../report/211155_20261117-phase-4.txt#L45-L48), `deep_mlp` บน `aggressive` ได้เพียง `1.76x` (`16.52 -> 9.40 ms`) และ `transformer_lm [small]` ใน [181819_20261117-phase-3.7.txt](../report/181819_20261117-phase-3.7.txt#L49-L51) ช่วง `steady` ยังอยู่ที่ `10.84 ms` เพราะ CPU ยังต้อง dispatch kernel สำหรับ forward/backward/optimizer ทีละรอบ (Launch-bound)
  - สาเหตุที่ยังเปิด `reduce-overhead` ตอนเทรนทันทีไม่ได้เพราะ CUDA Graphs ใน Training มีความเสี่ยงเรื่อง tensor storage overwrite (`cudagraph_mark_step_begin()`), dynamic shapes, และ CPU scalar branching (`.item()`)

## 2. ไฟล์เป้าหมาย
- `src/passes/auto_compile.py` — รองรับ safe training `reduce-overhead` (CUDA Graphs) ภายใต้ opt-in config (`compile.train_cuda_graphs`) หรือ `aggressive` เฉพาะโมเดล launch-bound ที่ผ่าน eligibility checks
- `src/config/schema.py` & `src/config/rules_builtin.py` — เพิ่ม `compile.train_cuda_graphs: bool = False` (และ guard บน CPU / `sm < 80` / low VRAM)
- `tests/unit/test_pass_compile.py` — ทดสอบ `cudagraph_mark_step_begin` invocation, dynamic-shape revert, และ skip when `.item()` / `GradScaler` / RNG mismatch risk detected
- `tests/migrate/test_phase5_4_train_cudagraphs.py` & `scripts/verify_phase5_4.py` — Benchmark `deep_mlp`, `cnn_vision:small`, `transformer_lm:small` บน Colab L4

## 3. งานย่อย (Implementation Tasks)
- [ ] **1. Eligibility & Profitability Gate สำหรับ Training CUDA Graphs**:
  - เปิดเฉพาะ when: CUDA `sm >= 80`, `compile.enabled=True`, static input shape คงที่ติดต่อกันอย่างน้อย 2 steps แรก (`warmup_shapes_stable == True`), **ไม่มี `Dropout` stochastic mask conflict** หรือใช้กับ `cudagraph_mark_step_begin()`, และโมเดลเป็นประเภท launch-bound (เช่น `deep_mlp` / small-to-medium CUDA modules)
  - **ห้ามเปิด** หรือ fallback กลับ `mode="default"` ทันทีหาก:
    - พบ shape เปลี่ยน (`dynamic=True`)
    - พบ `torch.cuda.amp.GradScaler` (`fp16` on T4 ที่มี conditional CPU `.item()` step skip)
    - เกิด CUDA Graph memory pool / overwriting error ตอน backward (`try/except` fallback กลับ `mode="default"`)
- [ ] **2. `torch.compiler.cudagraph_mark_step_begin()` Lifecycle Injection**:
  - เรียก `cudagraph_mark_step_begin()` (ถ้ามีใน PyTorch ปัจจุบัน) อัตโนมัติหน้า top-level `forward()` เมื่อ `train_cuda_graphs` ทำงาน และแยก stream/buffer ให้ปลอดภัยจาก output aliasing ตอน loss/backward
- [ ] **3. Schema & Profile Config Wiring**:
  - เพิ่ม `CompileConfig.train_cuda_graphs: bool = False` ใน Schema v1 (`supersafe`/`safe`/`balanced` ปิดไว้; `aggressive` หรือ `--override compile.train_cuda_graphs=true` ทดสอบเปิดในโมเดล static launch-bound)
