# Plan 5.2: Fused Chunked Linear + CrossEntropy Kernel (Zero Logits Materialization)

## 1. ปัญหาที่พบ & โอกาสเพิ่ม Speed / ลด VRAM
- ปัจจุบัน [`src/kernels/cross_entropy.py`](../src/kernels/cross_entropy.py) ช่วยเร่ง `CrossEntropy [large]` บน logits ขนาด `[8192, 8192]` ได้ถึง `3.55x vs Eager` (`3.362 ms`), **แต่ยังต้องรอให้ `lm_head` (`nn.Linear`) คำนวณ `logits = hidden @ weight.T` แล้วเขียน Tensor ขนาด `[Batch × Seq, Vocab]` เต็มก้อนลง HBM ก่อน!**
- ตัวอย่างสำหรับ LLM Vocabulary ใหญ่ (`Vocab = 32,000–128,000`, `N = 4096`):
  - แค่ Tensor `logits` ใน `FP32` / `BF16` ตัวเดียวกิน VRAM **`500 MB – 2,000 MB+`** และเสีย Memory Bandwidth อ่าน/เขียนซ้ำ 2 รอบ (Forward Linear + CrossEntropy Backward)

---

## 2. ไฟล์เป้าหมาย
- `src/kernels/fused_linear_cross_entropy.py` — Triton/Chunked PyTorch kernel คำนวณ `Linear + CrossEntropy` (Forward + Backward) ทีละ chunk (`CHUNK_N`) โดย **ไม่สร้าง logits ทั้งก้อนใน VRAM**
- `src/kernels/registry.py` — Auto-capture / hook คู่ pattern `(nn.Linear projection -> F.cross_entropy / nn.CrossEntropyLoss)` อย่างปลอดภัยเมื่อ `kernels.enabled=True`
- `tests/unit/test_fused_linear_ce.py` — Unit tests เทียบค่า Loss + Gradient (`d_hidden`, `d_weight`, `d_bias`) กับ Baseline `F.cross_entropy(F.linear(...))`, edge cases (`ignore_index`, `reduction="sum"|"mean"`, `bf16`/`fp16`/`fp32`, `N % chunk != 0`)
- `scripts/verify_phase5_2.py` — Large-vocab Scaling Benchmark (`V = 8192 / 32768 / 65536`) เทียบ Eager vs Compile vs `FusedLinearCrossEntropy`

## 3. งานย่อย (Implementation Tasks)
- [ ] **1. Chunked Exact Algorithm (`FusedLinearCrossEntropyFn(torch.autograd.Function)`)**:
  - รับ input `hidden [N, H]`, `weight [V, H]`, `bias [V] | None`, `targets [N]`, `ignore_index`, `label_smoothing=0.0`, `reduction`
  - **Forward pass**: แบ่ง `N` เป็นชิ้นเล็ก (`chunk_size = 1024` หรือ auto-tuned จาก `V` เพื่อให้ `[chunk_size, V]` <= ~16–32 MB):
    - คำนวณ `logits_chunk = hidden_chunk @ weight.T (+ bias)`
    - รัน `_cross_entropy_fwd_kernel` (จาก `src/kernels/cross_entropy.py`) เก็บเฉพาะ per-row `loss_chunk` และ `lse_chunk` — **ปล่อย `logits_chunk` ทิ้งทันที**!
  - **Backward pass**:
    - Recompute `logits_chunk` จาก `hidden_chunk @ weight.T` ทีละ chunk (Tensor Core gemm ไวกว่า HBM traffic ของ logits ขนาดยักษ์มาก)
    - รัน `_cross_entropy_bwd_kernel` ได้ `dlogits_chunk` ทันที
    - สะสม `d_hidden[chunk] = dlogits_chunk @ weight` และ `d_weight += dlogits_chunk.T @ hidden_chunk` (+ `d_bias += dlogits_chunk.sum(0)`), รองรับ AMP (`bf16`/`fp16`) โดย accumulate gradients ใน `fp32` แล้ว cast กลับ
- [ ] **2. Zero-Code Detection Pattern (`src/kernels/registry.py`)**:
  - เงื่อนไขเปิดใช้งานอัตโนมัติ (เฉพาะเมื่อปลอดภัย):
    - `cfg.kernels.enabled == True` (หรือ allow_list มี `"fused_linear_cross_entropy"`)
    - Tensor `weight` อยู่บน CUDA, `vocab_size >= 4096` (ถ้าเล็กกว่านี้อย่าเปิดเพราะ recompute อาจไม่คุ้ม)
    - ใช้เทคนิค lightweight **Deferred Output Provenance Tagging** เฉพาะบน CUDA `nn.Linear` ที่มี `out_features >= 4096` ใน `forward()`: หากผล `F.linear(x, w, b)` ที่เพิ่งสร้างถูกส่งตรงเข้า `F.cross_entropy(logits, target)` (และไม่มี consumer อื่นในระหว่างนั้น — หรือผ่าน safe tagged proxy context เฉพาะ training loop ที่เปิด `requires_grad`), แต่ออก fallback ทันทีถ้า `logits` ถูกนำไป slice/inspect ก่อนเข้า loss หรือ shape/args ไม่ตรงเกณฑ์!
  - *สำคัญ*: ต้องมี **Strict Guardrail** ห้ามทำให้ `model.state_dict()` หรือ `logits = model(x)` ที่ผู้ใช้เอา `logits` ไปใช้ต่ออย่างอื่นเพี้ยนหรือพังเด็ดขาด (ถ้าผู้ใช้เรียก `logits.argmax()` ก่อน loss -> fallback เป็น `F.cross_entropy` ปกติทันที!)
- [ ] **3. Micro & End-to-End Benchmark**:
  - วัด Peak Allocated VRAM, Step Time (`ms`), และ `d_weight` / `d_hidden` / `loss` MaxRelDiff เทียบ `F.cross_entropy(F.linear(...))` ที่ `V = 8192, 32000, 65536`

## 4. Tests & Success Criteria
- **Unit Parity (`tests/unit/test_fused_linear_ce.py`)**:
  - `MaxAbsDiff(loss) <= 1e-4` (FP32) / `<= 1e-2` (BF16)
  - `d_hidden`, `d_weight`, `d_bias` ตรงกับ PyTorch autograd reference ชัดเจน (`allclose`) รวมถึงกรณี `ignore_index=-100`, all-ignored chunk, non-contiguous slices (`[:, :-1, :]` reshaped), และ CPU fallback check
- **Benchmark & Deep Debug (`scripts/verify_phase5_2.py` -> `report/HHMMSS_YYYYMMDD-phase-5.2.txt`)**:
  - ใช้ `scripts/phase5_report_helper.py` ออกรายงานระดับ Phase 3 ครบ: Multi-scale Micro-Benchmark (`V = 8192, 32768, 65536`), End-to-End `Step0 / Med / P95 / P99 / E2E`, Deep Debug (`Phase Breakdown`, `Loss/Clip %`, `Backward %`), `CUDA Allocator & VRAM Headroom`, `Torch Profiler Top Ops` (ตรวจยืนยันว่า `aten::mm` logits buffer ขนาดยักษ์หายไป), และ `Per-Step Trace`
  - บน `V = 32,000+`, **Peak VRAM ต้องลดลงอย่างน้อย `40%–75%`** เมื่อเทียบ Eager/Compile และความเร็วเท่ากับหรือชนะ Compile โดยไม่มี regression ในงานปกติ
