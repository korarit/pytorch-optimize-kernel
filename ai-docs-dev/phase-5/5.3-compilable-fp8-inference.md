# Plan 5.3: Compilable FP8 Inference Fusion (`sm >= 89`)

## 1. ปัญหาที่พบจาก Benchmark จริง
- ในรายงาน [181115_20261117-phase-3.6.txt](../report/181115_20261117-phase-3.6.txt#L42-L46) (`NVIDIA L4 sm_89`):
  - `infer_bs64_large` + `3.6b_infer_amp_compile` (**BF16 + Compile**): **`89.89 ms` (`4.16x`)**, VRAM `-187.5 MB`
  - `infer_bs64_large` + `3.6d_fp8_sm89` (**Fused Triton FP8 Eager**): **`150.55 ms` (`2.48x`)**, VRAM `+198.8 MB`
- **สาเหตุใน [`src/passes/inference_opt.py`](../src/passes/inference_opt.py#L198-L245)**:
  - ใน `_fp8_forward` มีการเรียก `_get_triton_fp8_quantizer()` (custom raw Triton launch) + `torch_mod._scaled_mm(...)` อยู่ใน PyTorch wrapper แบบ Eager:
    1. เมื่อ `torch.compile` ทำงานด้วยกัน, custom raw Triton kernel คั่นกราฟให้แตกเป็น graph breaks -> Inductor ไม่สามารถ fuse activation quantize เข้ากับ `LayerNorm` / `GELU` / residual add ก่อนหน้าได้
    2. ตอนที่ `m_rows` ใหญ่, intermediate `x_q` + `scale` ของแต่ละ Linear ยังไม่ถูก reuse/fuse ในกราฟเดียวกับ op รอบข้าง ทำให้แพ้ `BF16 + Inductor fusion`

## 3. งานย่อย (Implementation Tasks)
- [ ] **1. Traceable / Compilable Activation Quantizer Path (`_quantize_fp8_traceable`)**:
  - เมื่อ `torch.compiler.is_compiling()` (หรือ `cfg.compile.enabled == True` บน CUDA):
    - ใช้ pure ATen pointwise ops ที่ TorchInductor รู้จักและ fuse กับ op ก่อนหน้าได้ใน 1 kernel (`amax`, clamp, scale, `.to(torch.float8_e4m3fn)`) ตามด้วย `torch._scaled_mm(..., out_dtype=..., bias=...)` โดยไม่มี `.item()` หรือ custom Triton break
    - เมื่อไม่ได้ compile (`compile=False`): ใช้ Fused Triton 2-pass quantizer (`_fp8_partial_amax_kernel` + `_fp8_quant_scale_kernel`) ตามเดิมเพื่อให้ Eager ยังได้ `2.48x`
- [ ] **2. Optimize Lazy Weight Cache Memory Overhead**:
  - ตรวจสอบ VRAM bloat (`+198.8 MB` ใน `infer_bs64_large`): เพิ่ม `PTOPT_FP8_DROP_BF16_EVAL=0` guard (คง safety `state_dict` เดิม 100%) และลด redundant contiguous copies บน `w_t` (pre-transpose once ตอนสร้าง cache ใน `col-major` layout ที่ `_scaled_mm` ต้องการโดยไม่สร้าง copy ซ้ำทุก step)
- [ ] **3. Shape & Compute-Intensity Threshold Calibration (`sm_89`)**:
  - ทดลอง benchmark จริงบน L4 (`infer_bs64_large` และ large Linear projection `M=2048..4096, K=4096, N=4096`) ระหว่าง:
    - `BF16 + Compile`
    - `FP8 Eager (Triton quant)`
    - `FP8 Compilable + Compile (Inductor)`
  - บันทึกผลลงรายงานว่าที่ scale ใด **`FP8 + Compile`** แซง **`BF16 + Compile`** และปรับ minimum shape gate (เช่น `in_features * out_features`) ให้เปิดเฉพาะจุดที่ FP8 ชนะ BF16 จริง

  - ยังคงรักษา `m_rows < 512` skip guard, `T4 sm_75` skip guard, และ `state_dict()` 100% untouched
