# Plan 5.1: Tiny Dynamic-Shape Compile & AMP Bypass (Profitability Gate)

## 1. ปัญหาที่พบจาก Benchmark จริง (`044642_20261118-phase-5.1.txt`)
- ในรายงาน [211155_20261117-phase-4.txt](../report/211155_20261117-phase-4.txt#L57-L60) และรอบแรก [044642_20261118-phase-5.1.txt](../report/044642_20261118-phase-5.1.txt#L16-L21) (NVIDIA L4 `sm_89`):
  - `edge_dynamic_only`: `safe` ได้ **`1.01x`** (`1.48 ms` vs `1.50 ms`, VRAM `+0.0 MB`), แต่ `balanced` ยังได้ **`0.81x`** (`1.86 ms`, VRAM **`+47.5 MB`**) และ `aggressive` ได้ **`0.84x`** (`1.79 ms`) แม้ Step 1 จะ revert `dynamic=True` กลับ Eager แล้ว!
- **สาเหตุ 2 ชั้นที่ต้องแก้ให้ขาด + พิสูจน์ด้วย Deep Debug**:
  1. **Step 0 Compile Scratch & Tiny Module Overhead (`src/passes/auto_compile.py`)**:
     - `Sequential` ใน `edge_cases` (`9,352` parameters, input `~5,376` elements) ถูกสั่ง `torch.compile()` ตั้งแต่ **Step 0** ก่อนจะรู้ว่า shape เปลี่ยนใน Step 1 ทำให้เสียเวลา compile Step 0 + จอง Inductor scratch `+47.5 MB` ใน `balanced`
     - นอกจากนี้ **Tiny-module profitability guard ควรเช็กทั้ง Step 0 และ Step 1** (เช่น skip `torch.compile` ตั้งแต่แรกถ้าโมเดลเล็กมากจน JIT/guardoverhead ไม่คุ้ม หรือปิด dynamic recompile on shape change)
  2. **Eager Auto-AMP & Python Wrapper Overhead บน Tiny CUDA MLPs (`src/passes/auto_amp.py`)**:
     - หลัง revert กลับ Eager แล้ว, `balanced`/`aggressive` ยังช้ากว่า `safe` อยู่ `+0.30–0.38 ms` (`1.86 ms` vs `1.48 ms`) เพราะยังเข้า `torch.amp.autocast(cuda, bf16)` และ wrap `F.cross_entropy` ในงานที่ tensor จิ๋วมาก (`< 100k` params, ไม่มี Conv/Attention — overhead การ cast & autocast dispatch สูงกว่าเวลา GEMM!)
