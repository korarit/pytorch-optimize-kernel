## เจาะลึกทีละ Sub-Phase: Root Cause, การแก้บั๊กเชิงลึก และผลลัพธ์

### 1. Phase 6.1: Zero-Sync AMP Watchdog, Unified Dispatcher & Single-Pass Train CUDA Graphs
- **สิ่งที่แก้ในสถาปัตยกรรม dispatch**:
  - สร้าง `ModuleCallDispatcher` ใน [`src/hooks/module_dispatch.py`](../../src/hooks/module_dispatch.py) รวม `nn.Module.__call__` ที่เดิมซ้อนกัน 6 ชั้นให้เหลือ wrapper หลักชั้นเดียว จัดลำดับคงที่ `kernels.auto (10) → runtime.activation_checkpointing (20) → inference.opt (30) → amp.auto (40) → runtime.channels_last (50) → compile.auto (60)` และมี recursive `iter_nested_tensors`, `build_shape_signature`, `has_cuda_context` แชร์ร่วมกันสำหรับ `dict`/`list`/`tuple` inputs (แทน helper ที่เคยเขียนซ้ำ)
  - แยก handle `_ptopt_train_compiled_impl` ออกจาก `_ptopt_eval_compiled_impl` ใน `auto_compile.py` และ `inference_opt.py` เพื่อรองรับโมเดลเดียวที่สลับ `.train()` ↔ `.eval()` ระหว่างเทรนกับ validation โดยไม่ทับสถานะ compile กัน
- **Zero-Sync Async AMP Stability Watchdog ([`auto_amp.py`](../../src/passes/auto_amp.py))**:
  - เปลี่ยน `check_loss_stability` จากการเรียก `.detach().cpu().item()` ทุก step เป็น `torch.isfinite(loss)` ลง async scalar tensor `_pending_finite_checks` บน GPU แล้วค่อยตรวจสอบครั้งเดียวในจังหวะ `optimizer.step` (ซึ่งอยู่ท้าย iteration และ sync น้อยกว่ากลาง graph)
- **Single-Pass Training CUDA Graphs ([`auto_compile.py`](../../src/passes/auto_compile.py))**:
  - เลื่อนการ compile จาก Step 0 (`mode="default"`) + Step 1 (`mode="reduce-overhead"`) มาเป็นรัน Step 0 ด้วย Eager เพื่อพิสูจน์ shape stability ร่วมกับ Step 1 แล้ว compile `mode="reduce-overhead"` ครั้งเดียวที่ Step 1; ลดเวลา compiler รวมลงเกือบครึ่งและยังให้ steady-state speedup **`1.81x–2.45x`** บน launch-bound workloads (`deep_mlp`: `3.79 ms`, `cnn_vision_small`: `4.57 ms`, `transformer_lm_small`: `4.88 ms`) ตามรายงาน [125213](../../report/125213_20261118-phase-6.1.txt)
  - เพิ่ม guard ให้ `mode="max-autotune"` บนโปรไฟล์ `aggressive`: หากโมเดลไม่ผ่านเกณฑ์ Training CUDA Graphs (เช่น มี `Dropout` หรือ `params > 15M`) ให้ถอยลงเป็น `max-autotune-no-cudagraphs` อัตโนมัติ

### 2. Phase 6.2: Hybrid `compile` + `FusedLinearCE` & Activation Checkpointing Recovery
- **Hybrid `torch.compile` Backbone + `FusedLinearCrossEntropy` Head**:
  - [`registry.py`](../../src/kernels/registry.py) เปิดโหมด Hybrid (`PTOPT_HYBRID_LCE=1`) ที่ปล่อยให้ Inductor compile Transformer/CNN backbone ตามปกติ แต่ครอบ terminal/large-vocab `nn.Linear` head (`sub is last_linear` หรือ `out_features > in_features * 4`, เกณฑ์ `>= 8192` ใน `balanced` / `>= 4096` ใน `aggressive`) ด้วย `@torch.compiler.disable` เพื่อส่ง `LazyLinearLogits` เข้า chunked `FusedLinearCrossEntropyFn`
  - ใน [`fused_linear_cross_entropy.py`](../../src/kernels/fused_linear_cross_entropy.py): ปรับ `FusedLinearCrossEntropyFn.backward` (เมื่อไม่ได้ใช้ `addmm_`) ให้จอง `dw_buf` ก้อนเดียวและใช้ `torch.mm(..., out=dw_buf)` วนซ้ำ ลด `fp16` `[V, H]` temp buffer; พร้อมขยาย `LazyLinearLogits` ให้รับ `.float()`, `.half()`, `.bfloat16()`, `.to(dtype)` แบบ lazy (`_ptopt_lazy_out_dtype`) โดยไม่ materialize ก่อนเข้า loss (Guardrail #4)
  - ผลบน `vocab32k`: Micro `fp16` ประหยัด VRAM **80.5%** (`1,624.4 → 316.5 MB`, `1.29x`), ส่วน E2E `hybrid_compile_lce` ทำได้ **`36.67 ms` (`3.40x`)** ใช้ VRAM **`1,199.0 MB`** (ลด `Alloc Ovhead` จาก `527.0 MB` ใน `balanced_compile` เหลือ **`15.0 MB`**)
- **Root Cause & Fix ของ Activation Checkpointing (`4.17x → 1.35x` และบั๊ก `_StopRecomputationError`)**:
  - **Root Cause #1 (จาก Phase 5.5 — False User-AMP Detection)**: ระหว่าง backward recomputation ภายใน `checkpoint(..., use_reentrant=False)`, submodule `__call__` ถูกเรียกซ้ำขณะที่ `ModuleCallDispatcher._depth == 0` ทำให้ `amp.auto` เห็น `autocast(bf16)` ของ Step 0 ที่ PyTorch restore ไว้แล้วเข้าใจผิดว่าผู้ใช้เปิด AMP เอง จึงตั้ง `user_amp_detected = True` และปิด BF16 AMP ทิ้งทุก step ถัดไป → แก้ด้วย `recompute_dispatch_guard(torch_mod)` ใน [`module_dispatch.py`](../../src/hooks/module_dispatch.py) ร่วมกับ [`activation_checkpoint.py`](../../src/passes/activation_checkpoint.py)
  - **Root Cause #2 (พบในรอบแรก [131406](../../report/131406_20261118-phase-6.2.txt) — `AssertionError: Unexpected state: target_frame.early_stop is set`)**: เมื่อเปิด `enable_custom_kernels_on_module` (Auto-Triton fallback หลัง `activation_checkpoint` ปิด `torch.compile`), Triton kernel wrappers (`triton_swiglu`, `triton_rmsnorm`, ฯลฯ) มี `except Exception:` ซึ่งไปจับ PyTorch `_StopRecomputationError` (subclass ของ `Exception` ที่ PyTorch โยนบน saved tensor ตัวสุดท้ายเพื่อทำ `early_stop=True`) แล้ว fallback กลับไปรัน Eager จนสร้าง tensor เกิน `weak_holders` → แก้ด้วย `_is_checkpoint_control_flow(exc)` ให้ re-raise `_StopRecomputationError` ทันทีในทุก wrapper ของ `registry.py` และ `_ckpt_forward`
  - เพิ่ม Strided Partial Checkpointing (`PTOPT_ACT_CKPT_RATIO=0.5` ใน `mode="auto"`, escalate เป็น `1.0` เมื่อ VRAM ยังสูง), Selective Activation Checkpointing (`PTOPT_ACT_CKPT_SAC=1`), เกณฑ์ block discovery `>= 10_000` params สำหรับ container ที่มี `len >= 4`, และ **Guardrail #2** Step-0 `OutOfMemoryError` catch-and-retry (เฉพาะ `mode="auto"` และไม่ใช่ `strict`)
  - ผลใน [134046](../../report/134046_20261118-phase-6.2.txt): `lm_act_med` (`act_ckpt_full_triton`) ฟื้นจาก `~167 ms` (`1.35x`) กลับมาที่ **`69.98 ms` (`3.19x` vs safe)** ประหยัด VRAM **52.5%** (`1,662.4 → 789.8 MB`) และ `strided_50pct` ได้ **`63.66 ms` (`3.50x`)** ประหยัด VRAM **30.0%**

### 3. Phase 6.3: LLM Triton Kernels, Static FP8 Refinements & Pipeline Polish
- **Zero-Copy Row-Strided Triton Kernels & Fused RoPE**:
  - เพิ่ม `triton_rope(q, k, cos, sin)` (Fwd+Bwd รองรับ GQA และตารางขนาด `D` หรือ `D//2`) และ `_to_row_strided_2d` ใน [`rope_or_swiglu.py`](../../src/kernels/rope_or_swiglu.py), [`rmsnorm.py`](../../src/kernels/rmsnorm.py), [`layernorm.py`](../../src/kernels/layernorm.py), [`cross_entropy.py`](../../src/kernels/cross_entropy.py) เพื่อรับ tensor ที่มี `stride(-1) == 1` (เช่น `gate_up.chunk(2, dim=-1)` หรือ logits slice) โดยไม่ copy
  - `rmsnorm.py` & `layernorm.py` เพิ่ม multi-row CTA packing (`ROWS_PER_CTA = 4..8` เมื่อ `N <= 1024`) โหลด `w`/`b` ครั้งเดียวต่อ CTA; `cross_entropy.py` ใช้ `tl.atomic_add(ValidCount_ptr, 1)` ใน kernel ลด 5 PyTorch micro-kernels นอก Triton
  - **Guardrail #1** ใน [`registry.py`](../../src/kernels/registry.py): `_match_swiglu_mlp` รองรับทั้ง `(w_gate, w_up, w_down)` และ HF `(gate_proj, up_proj, down_proj)` พร้อมตรวจ `act_fn` + `named_children()` ปฏิเสธ GeGLU (`GELU`) / ReGLU / Dropout MLP เด็ดขาด; `_is_verified_rope_inputs` ยืนยัน layout half-split ก่อนเปิด Triton RoPE
- **บั๊กและการแก้ไขสำคัญระหว่างรัน Verification (`141418 → 143528 → 145019`)**:
  1. **CUDA Optimizer Checkpoint Reload Bug (`141418` Fast Gate `10/14 FAIL`)**: ใน [`checkpoint_compat.py`](../../src/hooks/checkpoint_compat.py), `_compat_opt_load_state_dict` เคยเช็กเฉพาะ `capturable` ทำให้ `AdamW(fused=True, capturable=False)` บน CUDA ถูกย้าย `state[p]["step"]` กลับไปบน CPU จนแครชตอน resume → แก้ให้ตรวจ `bool(grp.get("capturable", False) or grp.get("fused", False))` (Guardrail #5a)
  2. **FP8 Dynamo Graph Breaks & MHA Prewarm (`141418` `143.48 ms` → `143528` `76.38–79.96 ms`)**: การเปิด `nn.MultiheadAttention` FP8 บน `d_model=768` โดยไม่มี weight prewarm + ใช้ `type("_W", ...)`/`try-except` ใน compile path ทำให้กราฟ Inductor แตก (Profiler แสดง `aten::gelu` `104.5 ms` unfused และ VRAM `965.6 MB`) และ Step-0 calibration เดิมรันใน `inference_mode()` โดยไม่เข้า `autocast` → แก้ให้ inline compiled Path 1 ล้วนปลอด graph break, prewarm cache ให้ MHA, gate MHA FP8 เป็น `embed_dim >= 1024` (หรือ `PTOPT_FP8_MHA=1`), และ calibrate ใน `no_grad() + autocast`
  3. **FusedLCE Triton Kernel Signature Drift (`143528` `errors=4`)**: `_chunk_ce_fwd` และ `_chunk_ce_bwd` ใน [`fused_linear_cross_entropy.py`](../../src/kernels/fused_linear_cross_entropy.py) ยังส่งอาร์กิวเมนต์ชุดเดิมให้ `_cross_entropy_*_kernel` ก่อน Phase 6.3 → ซิงก์อาร์กิวเมนต์ (`ValidCount_ptr`, `stride_targets`, `COUNT_VALID=False`) พร้อมเพิ่ม unit signature mock test; และปรับ [`test_pass_inference.py`](../../tests/unit/test_pass_inference.py) ให้ยอมรับ 1-ULP E4M3 mantissa rounding ภายใต้ Inductor fastmath
- **Pipeline, Heuristics & Guardrail #5**:
  - [`channels_last.py`](../../src/passes/channels_last.py): รองรับ heuristic volume (`B*C >= 4096 & H*W >= 4096`) และ `nn.Conv3d` (`channels_last_3d`)
  - [`optimizer_fusion.py`](../../src/passes/optimizer_fusion.py): ขยาย `foreach=True` ให้ `RMSprop`, `Adagrad`, `NAdam`, `RAdam` + opt-in `PTOPT_OPTIM_CAPTURABLE=1`
  - [`dataloader_tune.py`](../../src/passes/dataloader_tune.py) & [`auto_compile.py`](../../src/passes/auto_compile.py): cache CUDA prefetch stream ต่อ device บน `torch.cuda` และปิด `cudnn_benchmark` อัตโนมัติเมื่อพบ dynamic Conv shapes
  - [`fingerprint.py`](../../src/detect/fingerprint.py) (**Guardrail #5b**): disk cache static host/GPU fields ตาม `(hostname, CUDA_VISIBLE_DEVICES, executable, torch_ver, triton_ver, cuda_ver)` ลด cold probe จาก `2,124.2 → 108.0 ms` (`19.66x`) พร้อม probe `/dev/shm` สดทุกครั้งเสมอ และ bypass ได้ด้วย `PTOPT_NO_FP_CACHE=1`

## สรุปการรักษาหลักการ Zero-Code (Architecture Preservation) หลังจบ Phase 6

1. **Zero Code Edit on Target Pipelines**: ทุกเวิร์กโหลดภายใต้ `pipline-for-test/workloads/*.py` ทำงานผ่าน `ptopt -- <cmd>` และ `sitecustomize.py` โดยไม่แก้ซอร์สโค้ดโมเดล/เทรนสคริปต์เดิม
2. **Zero External Dependencies**: [`pyproject.toml`](../../pyproject.toml) ยังคง `dependencies = []` (Python stdlib + optional PyTorch/Triton ของระบบผู้ใช้)
3. **Checkpoint & `state_dict()` Parity 100%**: ผ่าน `test_checkpoint_compat.py`, `test_checkpoint_migration_matrix.py`, `test_phase5_4_train_cudagraphs.py` ครบทั้งหมดใน `Fast Gate (14/14 PASS)` ([145019](../../report/145019_20261118-phase-6.3.txt))
4. **ข้อจำกัดที่ยังเปิดไว้ชัดเจน**: `fp8_compile_static` (`PTOPT_FP8_STATIC_SCALE=1`) และ `capturable=True` (`PTOPT_OPTIM_CAPTURABLE=1`) ยังคงเป็น **opt-in** เพื่อไม่เพิ่ม latency/VRAM warmup ของ Stepped/Short runs ที่ค่าเริ่มต้น `balanced`/`aggressive` ทำได้ดีอยู่แล้ว
