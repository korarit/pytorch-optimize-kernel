## เจาะลึก 4 จุดสำคัญที่แก้แล้วเห็นผลชัดเจน

### 1. เหตุใด `fp8_compile_static` จึงหายทั้ง Tail Spike (`10.2s → 90ms`) และ Calibration VRAM Bloat (`1,909.8 → 1,061.8 MB`)
1. **การจัดลำดับ Hook & `suppress()`**:
   - เดิม [`HookManager.apply_torch_hooks()`](../../ptopt/hooks/manager.py) ติดตั้ง [`TelemetryCollector`](../../ptopt/hooks/telemetry_hook.py) ก่อน passes ทำให้ `ModuleCallDispatcher` มาหุ้มซ้อนอยู่ด้านนอก เมื่อ `inference_opt` เรียก `mod_self._call_impl(*args)` ตอน calibrate ขณะที่ `TelemetryCollector._module_depth == 0` โมดูลลูก 4 ชิ้นใน Transformer จึงถูกบันทึกเป็น 4 fake steps (`s0..s3`) แล้วผลัก `torch.compile` ตัวจริงของ Step 0 ไปตกที่ `s4` กลาง steady window
   - เมื่อย้าย telemetry ไปติดตั้ง **หลัง** passes + ครอบ `suppress()` รอบ calibration loop แล้ว, `TelSteps` กลับมาตรงที่ `10` steps เป๊ะ และ Step-0 compile (`12.5s`) อยู่ใน `s0` ตามจริง ส่วน `s1..s9` วิ่งนิ่งที่ **`86.25–90.11 ms`** (ไม่มี `amax()` reduction kernel ใน profiler `[4, 9]`)
2. **Micro-Batch Calibration Slicing (`_slice_fp8_calib_inputs`)**:
   - รอบแรก ([055700](../../report/055700_20261119-phase-7.txt)) การรัน eager calibration `2` รอบบน batch เต็ม `B=64, S=512` สร้าง eager FFN/LayerNorm intermediates ซ้อนบนตัวจัดสรรความจำถึง `1,909.8 MB` (`Overhead 500.2 MB`)
   - การตัดเฉพาะ batch ช่วง calibration ให้พอดี `M >= 512` (`B_calib=2` -> `M=1024`, ขยับ offset `[0:2]` และ `[2:4]` พร้อม automatic full-batch fallback + `cuda.empty_cache()`) ลด calibration VRAM เหลือ **`1,061.8 MB` (`Overhead 68.2 MB`)** เท่า `fp8_compile_dynamic` และประหยัดกว่า `eager_bf16` ถึง **`-390.7 MB`**

### 2. การแก้ `LazyLinearLogits` ให้ผ่าน Dynamo Boundary (`compiled forward() + F.cross_entropy`)
- PyTorch `torch.Tensor._make_subclass(cls, meta, require_grad=True)` เมื่อถูกเรียกในบริบทที่มี gradient active จะติดสถานะ `_is_view=True` (`<ViewBackward0>`) โดยไม่มี autograd `CreationMeta` ทำให้เมื่อส่งกลับข้ามขอบ `@torch.compiler.disable` เข้าสู่ Dynamo resume frame แล้วพัง `InternalTorchDynamoError: Expected meta != nullptr to be true`
- ใน [`LazyLinearLogits`](../../ptopt/kernels/fused_linear_cross_entropy.py) แก้โดยสร้าง zero-stride backing storage (`torch.empty_strided(out_shape, (0,)*ndim, device=hidden.device)` ใช้จริงเพียง <= 4 bytes) ภายใต้ `with torch.no_grad():`, กำหนด `requires_grad_()` หลังผูก state แล้วภายใต้ `DisableTorchFunctionSubclass()`, และส่งผ่าน metadata queries (`_is_view`, `untyped_storage`, `storage_offset`, `stride`, `is_conj`, `is_neg`, `is_contiguous`, ฯลฯ) โดยไม่ trigger `materialize()` ก่อนถึง `F.cross_entropy`

### 3. ความปลอดภัยข้ามเวอร์ชัน Python 3.13 / Google Colab
- ใน `055700` พบว่า Colab มีแพ็กเกจ `tests` ใน `/usr/local/lib/python3.13/dist-packages/` ซึ่งบัง namespace `./tests` เมื่อรัน `python -m unittest tests/unit/...` — ปรับ [verify_phase7.py](../../scripts/verify_phase7.py) ให้เรียกตรงตาม path (`[sys.executable, str(REPO_ROOT / rel_path), "-v"]`) จึงผ่านครบ **`11/11`** (`test_phase7_features.py`) บนทั้ง Python 3.12 และ Python 3.13 Colab
