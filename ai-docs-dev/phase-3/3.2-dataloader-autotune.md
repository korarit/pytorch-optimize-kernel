# Phase 3.2: DataLoader Auto-Tuning & Colab `/dev/shm` + Pickle Guard

## เป้าหมาย (Goal)
เร่งความเร็ว Data Pipeline โดยการดักและปรับพารามิเตอร์ของ `torch.utils.data.DataLoader` อัตโนมัติ พร้อมระบบป้องกันปัญหาคลาสสิกบน Google Colab/Docker (เช่น `/dev/shm` เต็ม และ Dataset ที่ pickle ไม่ได้)

---

---

## งานทดลองแบบละเอียด (Experiment Tasks)
- [x] **Safe Parameter Injection**:
  - ปรับ `pin_memory=True` (เมื่อ target training device เป็น CUDA และ dataset ไม่ได้คืน CUDA tensor อยู่แล้ว)
  - ทดลองปรับ `num_workers` อัตโนมัติ (เฉพาะเมื่อโค้ดเดิมตั้ง `num_workers=0` และเข้าเงื่อนไขปลอดภัย) + `persistent_workers=True` + `prefetch_factor`
- [x] **Colab Safety Guards (สำคัญมาก)**:
  - **Shared Memory Guard**: เช็ก `shm_size_mb` (ถ้า `/dev/shm < 2048 MB` เช่นบาง container หรือ Colab runtime จำกัด → บังคับ cap `num_workers <= 2` หรือไม่ auto-bump)
  - **Pickle-ability Guard**: ตรวจเบื้องต้นว่า `dataset` / `collate_fn` สามารถ pickle ได้ (เช่น `pickle.dumps` หรือ inspect closure/lambda) ถ้าไม่ได้ → คง `num_workers=0` และบันทึกเหตุผลลง Fallback Log
  - **Runtime Fallback**: ถ้าเปิด worker แล้วพังระหว่างสร้าง iterator → fallback กลับ config เดิมของ user อัตโนมัติ
- [x] ทดลองวัดผลว่า `num_workers` ค่าไหน (`0`, `2`, `4`) ให้ throughput ดีที่สุดบน Colab CPU 2-core / 8-core โดยไม่กิน RAM/shm เกิน
