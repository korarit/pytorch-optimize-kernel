# Phase 3.5: Inference / Running Optimization

## เป้าหมาย (Goal)
เร่งความเร็วฝั่ง **Running / Inference** (ทั้ง Latency ของ Batch=1 และ Throughput ของ Batch=N) โดยไม่ต้องแก้โค้ด inference เดิม

---

## ไฟล์และโมดูลเป้าหมาย
- `src/passes/inference_opt.py` — Auto `torch.inference_mode()` guard, `reduce-overhead` compile / CUDA Graphs experiment, Dynamic Quantization / FP8 hooks
- `tests/unit/test_pass_inference.py` — Unit tests สำหรับ eval/grad detection และ quantization/FP8 hardware gate
- `scripts/exp_phase3_5.py` — ทดลอง Latency & Throughput บน `infer_runner.py` (Batch=1 และ Batch=64)

---

## งานทดลองแบบละเอียด (Experiment Tasks)
- [ ] **Safe `inference_mode()` Injection**:
  - ทดลองตรวจจับบริบทที่โมเดลอยู่ใน `.eval()` (และไม่มีการใช้ `torch.enable_grad()` / backward context) แล้วครอบด้วย `torch.inference_mode()` อัตโนมัติ
  - **Safety Guard**: ห้ามไปตัด gradient ถ้าโค้ดกำลังทำ validation loss แบบที่อาจสลับกลับมา train ใน process เดียวกัน หรือถ้า `requires_grad` ถูกขอโดยตั้งใจ (เช่น adversarial/RL/PINN) → ต้องทดสอบ edge case นี้!
- [ ] **CUDA Graphs / `torch.compile(mode="reduce-overhead")`**:
  - ทดลองวัด Latency Gain บน `infer_runner.py --batch-size 1` (ซึ่งมักติด CPU kernel launch overhead หนักบน GPU)
  - ตรวจจับ fallback กรณี shape ไม่คงที่ (dynamic batch/seq_len)
- [ ] **Quantization / FP8 Hooks (Optional / Aggressive & Arch-Gated)**:
  - ทดลอง `torch.ao.quantization.quantize_dynamic` สำหรับ CPU inference (`x86_64` / `aarch64`)
  - ทดลอง FP8 path เฉพาะบน GPU `sm >= 89` (L4 / H100) พร้อม numerical accuracy check
