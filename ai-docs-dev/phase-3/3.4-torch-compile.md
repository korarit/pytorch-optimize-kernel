# Phase 3.4: Auto `torch.compile`, Persistent Cache & Checkpoint Transparency

## เป้าหมาย (Goal)
ทดลองนำ `torch.compile` มาครอบโมเดลโดยอัตโนมัติ พร้อมจัดการ **Cold vs Warm compile cache**, **Dynamic Shape / Graph Break Fallback**, และแก้ปัญหาคลาสสิก **`_orig_mod.` prefix ใน `state_dict()`** เพื่อให้ Checkpoint Migrate Test ผ่าน 100%

---

## ไฟล์และโมดูลเป้าหมาย
- `src/passes/auto_compile.py` — Safe lazy/once model compilation + dynamic shape & failure fallback + cache dir management
- `src/hooks/checkpoint_compat.py` — เสริม `state_dict` / `load_state_dict` wrapper สำหรับ `OptimizedModule` (`_orig_mod.`)
- `tests/unit/test_pass_compile.py` — Unit tests สำหรับ compile guard, mock failure fallback และ `_orig_mod.` normalization
- `scripts/exp_phase3_4.py` — วัด **Cold Run vs Warm Run** บน Colab ทุก workload

---

## งานทดลองแบบละเอียด (Experiment Tasks)
- [ ] **Compile Injection Strategy**:
  - ทดลองหาจังหวะ compile ที่ปลอดภัยที่สุด (เช่น ดักตอนส่ง `model.parameters()` เข้า `Optimizer.__init__` หรือก่อน first forward บน GPU, และเช็กว่าไม่ถูก compile ซ้ำ)
  - ทดลองเลือก `mode` ตาม Hardware & Profile (`default` สำหรับ `balanced`, `max-autotune` สำหรับ `aggressive` บน GPU VRAM สูง, ปิด/conservative บน VRAM ต่ำ)
- [ ] **Cache & Warmup Analysis (สำคัญมากสำหรับ Colab)**:
  - ตั้ง `TORCHINDUCTOR_CACHE_DIR` ในพื้นที่ถาวร/ที่กำหนดได้
  - วัดเทียบให้เห็นชัดเจนทั้ง **Cold Cache Run** (Compile time + Step time) และ **Warm Cache Run** เพื่อรู้ว่าต้องรันกี่ step ถึงจะ "คุ้มทุน"
- [ ] **Fallback & Dynamic Shape Guards**:
  - ใช้ `torch._dynamo.config.suppress_errors` หรือ wrapper fallback หาก compile ล้มเหลวระหว่างรัน
  - ทดสอบกับ `edge_cases.py` (input shape เปลี่ยนทุก step): วัดว่า recompilation limit ทำงานไหม และ fallback หรือใช้ `dynamic=True` อย่างไหนดีกว่า
- [ ] **Checkpoint Transparency**:
  - เมื่อ `torch.save(model.state_dict())` ถูกเรียกบนโมเดลที่ถูก compile (`OptimizedModule`) ต้อง strip prefix `_orig_mod.` ออกให้อัตโนมัติ (หรือคง compatibility ทั้ง 2 ฝั่ง) เพื่อให้โหลดกลับใน PyTorch ปกติได้ทันที
