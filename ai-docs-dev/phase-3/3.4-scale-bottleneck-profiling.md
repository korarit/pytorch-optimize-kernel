# Phase 3.4: Scale-Up Bottleneck Profiling & Detailed Debug Diagnostics

## เป้าหมาย (Goal)
ทดสอบและวิเคราะห์คอขวดเชิงลึก (**Small vs Medium vs Large Model Scale**) บน GPU จริงก่อนเข้า `torch.compile` (Phase 3.5) เพื่อ:
1. วัดให้เห็นชัดว่าเมื่อเพิ่มขนาดโมเดล/Batch/Resolution (`transformer_lm`, `cnn_vision`, `deep_mlp`) แล้วจุดใดที่ **Phase 3.1–3.3** (`Runtime Flags`, `DataLoader`, `Fused Optimizer`, `Auto-AMP bf16/fp16`) เริ่ม **เร่งความเร็วได้จริง** และจุดใดยังติดคอขวดอยู่
2. เพิ่ม **Deep Debug Profiler** (opt-in ผ่าน `PTOPT_DEBUG_PROFILE=1` และ `PTOPT_TORCH_PROFILE=1`) ที่รายงาน breakdown ราย phase ของแต่ละ step (`Data/Other`, `Forward`, `Loss/Gap`, `Backward`, `Optimizer.step`), `Warmup Step 0` vs `Steady-State`, CUDA Allocator stats (`alloc_retries`, `reserved overhead`, `VRAM headroom`), และ Top CUDA/CPU Ops จาก `torch.profiler`
3. สรุป **Bottleneck Classification & Auto-Diagnosis Recommendations** เพื่อใช้วางแผน threshold ของ `balanced` profile และจัดลำดับเป้าหมายใน Phase 3.5 (`torch.compile`), 3.6 (`Inference`) และ 3.7 (`Custom Kernels`)

## งานทดลองแบบละเอียด (Experiment Tasks)
- [x] **Opt-in Deep Debug Telemetry (`TelemetryCollector`)**:
  - เมื่อ `PTOPT_DEBUG_PROFILE=1`: วัดเวลาแยก 5 ช่วงต่อ step (`data_other_ms`, `forward_ms`, `loss_ms`, `backward_ms`, `optim_ms`) พร้อม `cuda.synchronize()` ที่ขอบแต่ละ phase และเก็บ step-by-step trace + Warmup vs Steady-State (`step 0` vs steady median/p95)
  - เก็บ `memory_stats()` เชิงลึก (`peak_allocated`, `peak_reserved`, `reserved_overhead`, `total_vram`, `headroom`, `num_alloc_retries`, `num_ooms`)
  - เมื่อ `PTOPT_TORCH_PROFILE=1`: เปิด `torch.profiler.profile` เฉพาะช่วง steady-state window (เช่น steps 3–6) เพื่อสรุป Top CPU/CUDA Ops พร้อมเปอร์เซ็นต์เวลาและจำนวนครั้งที่เรียก
- [x] **Multi-Scale Bottleneck Sweep (ไม่แก้ไขโค้ด workloads ใช้ CLI scaling flags เดิม)**:
  - `transformer_lm`: Small (`d256 L4 seq128 bs16`) vs Medium (`d512 L6 seq256 bs16`) vs Large (`d768 L12 seq512 bs16`)
  - `cnn_vision`: Small (`64x64 w64 bs32`) vs Medium (`128x128 w96 bs32`) vs Large (`224x224 w128 bs32`)
  - `deep_mlp`: Small (`w256 d24 bs64`) vs Medium (`w1024 d24 bs128`) vs Large (`w2048 d24 bs256`)
- [x] **Automated Bottleneck Diagnosis**:
  - จำแนกแต่ละ scale tier เป็น `LAUNCH_OR_HOST_BOUND`, `DATALOADER_OR_H2D_BOUND`, `COMPUTE_OR_BACKWARD_BOUND`, `OPTIMIZER_BOUND`, หรือ `AMP_EAGER_OVERHEAD` พร้อมคำแนะนำเชิงตัวเลขสำหรับ Phase 3.5–3.7
