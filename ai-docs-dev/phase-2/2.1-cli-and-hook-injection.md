# Phase 2.1: CLI Launcher & `sitecustomize` Hook Injection

## เป้าหมาย (Goal)
สร้างตัวเปิดคำสั่ง (`ptopt`) และกลไก inject hook (`sitecustomize.py`) ที่แทรกตัวเข้า Python process และ worker subprocesses ได้อัตโนมัติโดยไม่ต้องแก้โค้ดเป้าหมาย พร้อม Idempotency Guard และ Safe Fallback

> หมายเหตุ: ใน Sub-Phase 2.1 เปิดเฉพาะโหมด passthrough / hook registry เปล่า ๆ เพื่อให้แน่ใจว่าท่อ injection เสถียร 100%

---

## ไฟล์และโมดูลเป้าหมาย
- `pyproject.toml` — กำหนด package และ console script `ptopt` (ติดตั้งแบบ `pip install -e .` บน Colab ได้ทันที)
- `src/cli/main.py` — CLI parser รองรับ `ptopt [--profile ...] [--no-compile] -- <cmd...>` หรือ `ptopt python train.py ...`
- `src/hooks/bootstrap/sitecustomize.py` — Auto-bootstrap เมื่อ Python start
- `src/hooks/manager.py` — Hook lifecycle, Idempotency guard, Fallback tracker, `sitecustomize` chain-loader (ไม่ทับ `sitecustomize.py` เดิมของ environment ถ้ามี!)
- `tests/unit/test_cli_hooks.py` — Unit tests ของ CLI และ Hook injection
- `scripts/verify_phase2_1.py` — Test & report script

## งานย่อยแบบละเอียด (Tasks)
- [x] **CLI Wrapper**:
  - รองรับทั้ง `ptopt -- python train.py --lr 1e-3` และ `ptopt train.py --lr 1e-3`
  - ส่งต่อ `exit code`, `stdin`, `stdout`, `stderr`, และ signal (`SIGINT`/`SIGTERM`) ของ user process ครบถ้วน
  - เซ็ต `PYTHONPATH` โดยเอา path ของ `src/hooks/bootstrap/` วางหน้าสุด (และยังคง `PYTHONPATH` เดิมของผู้ใช้ไว้) + ส่ง resolved config ผ่าน env (`PTOPT_ACTIVE=1`, `PTOPT_CONFIG_JSON=...`)
- [x] **Safe `sitecustomize.py` Chain-Loader**:
  - ตรวจหาว่ามี `sitecustomize.py` เดิมของระบบ/Colab อยู่หรือไม่ ถ้ามีให้โหลดของเดิมต่อด้วย เพื่อไม่ให้ไปพังเครื่องมือของ Colab
  - ป้องกัน infinite recursion / double initialization ด้วย sentinel flag (`_PTOPT_BOOTSTRAPPED`)
  - รองรับ lazy hook เมื่อ `torch` ถูก import (ใช้ `sys.meta_path` import hook หรือ post-import callback เพื่อไม่ให้ชะลอ script ที่ไม่ได้ใช้ torch และดักก่อน user script เรียก `torch.*`)
- [x] **Fallback & Error Isolation**:
  - ถ้า pass ใด error ระหว่าง patch ให้จับ exception เก็บลง `FallbackRegistry` และปล่อยให้ user script รันต่อได้ (ยกเว้นตั้ง `--strict`)
