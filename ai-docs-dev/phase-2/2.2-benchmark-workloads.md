# Phase 2.2: Representative Pure PyTorch Workloads & Edge-Case Scripts

## เป้าหมาย (Goal)
สร้างชุด Workload ตัวแทนและ Edge-case scripts ใน `pipline-for-test/workloads/` ที่เป็น **Pure PyTorch 100%** (ห้าม import โค้ดของ wrapper เด็ดขาด) เพื่อใช้เป็นสนามทดสอบมาตรฐานทั้งในด้าน Speed, VRAM, Parity และ Safety

---

## ไฟล์และโมดูลเป้าหมาย
- `pipline-for-test/workloads/__init__.py`
- `pipline-for-test/workloads/cnn_vision.py` — CNN + CPU data augmentation (DataLoader/CPU/TF32/channels_last bottleneck)
- `pipline-for-test/workloads/transformer_lm.py` — Tiny-GPT / Transformer (Attention/AMP/Compile/Triton Kernel bottleneck)
- `pipline-for-test/workloads/deep_mlp.py` — Deep narrow MLP หลาย layer (Kernel launch & Optimizer-step overhead bottleneck)
- `pipline-for-test/workloads/infer_runner.py` — Inference workload (รองรับ `--batch-size 1` latency และ `--batch-size 64` throughput)
- `pipline-for-test/workloads/edge_cases.py` — Edge cases ที่ wrapper ต้องห้ามทำพัง
- `scripts/verify_phase2_2.py` — Smoke run workloads บน Baseline PyTorch แล้วออก report

---

## งานย่อยแบบละเอียด (Tasks)
- [ ] ออกแบบ CLI กลางของทุก workload (`--steps`, `--batch-size`, `--seed`, `--device`, `--save-ckpt`, `--load-ckpt`)
- [ ] **Workload 1 (`cnn_vision.py`)**:
  - ResNet-like / ConvNet + Synthetic image dataset + CPU transforms (จำลอง DataLoader bottleneck)
- [ ] **Workload 2 (`transformer_lm.py`)**:
  - Decoder-only Transformer (Multi-head self-attention + RMSNorm/LayerNorm + SwiGLU/MLP + CrossEntropyLoss)
- [ ] **Workload 3 (`deep_mlp.py`)**:
  - โมเดลที่เต็มไปด้วย Linear/Activation ขนาดเล็กจำนวนมาก + AdamW
- [ ] **Workload 4 (`infer_runner.py`)**:
  - โหลด model (หรือสร้าง deterministic weights) แล้วรัน eval loop ทั้ง single-sample และ batched
- [ ] **Workload 5 (`edge_cases.py`)** (3 เคสในสคริปต์เดียวหรือ subcommands):
  1. สคริปต์ที่เปิด `torch.amp.autocast` + `GradScaler` เองอยู่แล้ว
  2. สคริปต์ที่ input tensor เปลี่ยน shape ทุก step (dynamic shape test)
  3. สคริปต์ที่ Dataset มี lambda/closure ไม่สามารถ pickle ข้าม multiprocessing workers ได้ (`num_workers=0`)
- [ ] กำหนดขนาด default ให้รันจบบน Google Colab (ทั้ง GPU T4/L4/A100 และ CPU fallback) ภายในเวลาเหมาะสม (เช่น 5–30 วินาทีต่อ workload)
