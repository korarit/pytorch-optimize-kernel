# Phase 4.1: Full 3-Axis Migrate Test Matrix

## เป้าหมาย (Goal)
ขยายชุด **Migrate Tests** ให้ครอบคลุมทั้ง 3 มิติ (Code Migration, Checkpoint Migration, Config/Cache Migration) เพื่อรับประกันว่าระบบทำงานเข้ากับโค้ด PyTorch หลากหลายสไตล์และการอัปเกรดเวอร์ชันได้จริง

---

## ไฟล์และโมดูลเป้าหมาย
- `src/config/migrator.py` — Auto-migrator สำหรับ config schema เวอร์ชันเก่า + cache key validator (ผูกกับ GPU arch + PyTorch version)
- `tests/migrate/test_code_migration_matrix.py` — Axis 1: Legacy & Complex PyTorch script styles
- `tests/migrate/test_checkpoint_migration_matrix.py` — Axis 2: Cross-mode Checkpoint + Optimizer state migration
- `tests/migrate/test_config_cache_migration.py` — Axis 3: Config schema & compile cache migration
- `scripts/verify_phase4_1.py` — รัน Migrate Matrix ทั้งหมดแล้วออก Text Report

---

## งานย่อยแบบละเอียด (Tasks)
- [ ] **Axis 1: Code Migration Matrix (`test_code_migration_matrix.py`)**:
  - Legacy PyTorch 1.x `torch.cuda.amp.autocast()` + `GradScaler()` syntax
  - Training loop ที่มี **Gradient Accumulation** (`loss / accum_steps`, `backward()` หลายครั้งก่อน `optimizer.step()`)
  - Training loop ที่มี **Multi-Optimizer** หรือ **LR Scheduler** (`CosineAnnealingLR`, `OneCycleLR`)
  - โมเดลที่มี **Custom `torch.autograd.Function`** และ **Dynamic control flow** (`if/else` ตามค่า tensor)
  - Training + Eval สลับใน loop เดียวกัน (ตรวจทั้ง `inference_opt` และ `auto_amp` ว่าไม่ขัดกัน)
- [ ] **Axis 2: Checkpoint & Optimizer State Migration (`test_checkpoint_migration_matrix.py`)**:
  - Cross-load matrix ครบทุกคู่: `Baseline` ↔ `safe` ↔ `balanced` ↔ `aggressive`
  - ทดสอบโหลดทั้ง `model.state_dict()`, `optimizer.state_dict()`, และ `scaler.state_dict()` (กรณี T4 `fp16`)
  - ตรวจ tensor keys, shapes, dtypes และ numerical continuity ของ loss หลัง resume
- [ ] **Axis 3: Config & Cache Schema Migration (`test_config_cache_migration.py`)**:
  - สร้าง mock config schema v0/legacy → ทดสอบ `migrator.py` แปลงเป็น Schema v1 อัตโนมัติพร้อมคำเตือนชัดเจน
  - ทดสอบ Inductor/Triton cache key ที่ผูกกับ `(gpu_arch, torch_version, triton_version)` → ถ้าเปลี่ยน runtime/GPU ต้องไม่โหลด cache เก่าที่ผิด architecture มาใช้จนพัง
