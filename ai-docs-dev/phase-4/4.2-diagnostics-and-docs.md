# Phase 4.2: Diagnostics (`--doctor`), Fallback Reporter & Documentation

## เป้าหมาย (Goal)
สร้างเครื่องมือวินิจฉัยปัญหาและรายงานสิ่งที่เกิดขึ้นจริงตอนรัน (`--doctor`, `--fallback-report`) เพื่อให้ผู้ใช้ตรวจสอบความพร้อมของ Google Colab / เครื่องปลายทางได้ง่าย พร้อมคู่มือการใช้งานและขยายระบบ

---

## ไฟล์และโมดูลเป้าหมาย
- `src/cli/doctor.py` — `ptopt --doctor` ตรวจระบบและให้คำแนะนำเฉพาะเครื่อง
- `src/hooks/fallback_reporter.py` — สรุปสถานะ Pass ที่เปิดใช้จริง vs Pass ที่ถูก skip/fallback พร้อมเหตุผล
- `tests/unit/test_doctor_and_fallback.py` — Unit tests ของ doctor checks และ fallback report formatting
- `ai-docs-dev/USER-GUIDE.md` — คู่มือการใช้งาน CLI, Profiles, Colab usage และวิธีเขียน Optimization Pass / Custom Kernel ใหม่
- `scripts/verify_phase4_2.py` — ทดสอบ `--doctor` + `--fallback-report` แล้วออก Text Report

---

## งานย่อยแบบละเอียด (Tasks)
- [ ] **`ptopt --doctor`**:
  - ตรวจ CUDA driver/runtime, PyTorch version, Triton availability, `/dev/shm` free/total size, `libjemalloc`/`libtcmalloc`, write permission ของ `TORCHINDUCTOR_CACHE_DIR` และ `report/`
  - แนะนำ Profile ที่เหมาะกับเครื่องปัจจุบัน (เช่น "Detected Colab T4 sm_75 + 15GB VRAM + 2GB /dev/shm → recommended: balanced (fp16 AMP, TF32 off)")
  - ให้คะแนน/สถานะ `[OK]`, `[WARN]`, `[MISSING]` พร้อมวิธีแก้ (เช่น command `apt`/`pip` สำหรับ Colab ถ้าอยากเปิดฟีเจอร์เสริม)
- [ ] **`--fallback-report` & Text Report Integration**:
  - ตอนจบการทำงานของคำสั่ง `ptopt`, พิมพ์สรุป (ถ้าเปิด `--fallback-report` หรือ `--verbose`) และสามารถสั่ง `--save-report report/` เพื่อเขียนเป็น `report/HHMMSS_YYYYMMDD-run-<name>.txt`
  - แยกชัดเจนว่า pass ไหน `[APPLIED]`, `[SKIPPED (by arch/config)]`, `[FALLBACK (runtime error)]`
- [ ] **Documentation (`ai-docs-dev/USER-GUIDE.md`)**:
  - วิธีรันบน Google Colab แบบ step-by-step
  - วิธีเพิ่ม GPU Rule ใหม่ และวิธีสร้าง Custom Kernel + Unit/Migrate tests
